# spike — Nuxt and Vue conventions

Throwaway Nuxt 4 app; see `README.md` for what it is for and how to run it. It gets
deleted rather than promoted, so favour the straightforward version of anything here.
Workspace-wide rules live in the root `CLAUDE.md` and still apply.

## Nuxt 4 puts the app in `app/`

`srcDir` defaults to `app/`, and this is the single most common thing to get wrong,
because Nuxt 3 tutorials and muscle memory both put these at the package root:

```
spike/
├─ app/            components/ composables/ layouts/ middleware/ pages/
│                  plugins/ utils/ assets/ app.vue error.vue
├─ server/         api/ routes/ middleware/   ← package root, not app/
├─ shared/         types and utils used by both the Vue app and Nitro
├─ public/         served as-is
└─ nuxt.config.ts
```

`server/`, `shared/` and `public/` resolve relative to the package root. Everything
the Vue app owns resolves from `app/`. If an auto-import is not resolving, this is
the first thing to check.

## Auto-imports

Vue APIs, Nuxt composables, and anything in `app/composables/`, `app/utils/` and
`app/components/` are auto-imported. Do not write manual import statements for them;
the generated `.nuxt/imports.d.ts` and `.nuxt/components.d.ts` are what make the
editor resolve them. Both are regenerated by `nuxt prepare`, which runs on install.

Nothing under `.nuxt/` is editable. It is generated output, including the ESLint
config this package composes with.

## Component naming

Nuxt derives the tag from the path, prefixing nested directories:
`app/components/user/card.vue` is `<UserCard>`, not `<Card>`.

`vue/multi-word-component-names` is an error here, switched back on over antfu's
preset because single-word tags collide with current and future HTML elements. Nuxt's
own ESLint layer exempts the paths where the filename is a routing contract rather
than a tag you write: `app/app.*`, `app/error.*`, `app/layouts/**`, `app/pages/**`,
and `app/components/*/**`. That last one is subdirectories only, and it is exempt
precisely because directory prefixing already makes the tag multi-word.

So `pages/about.vue` and `components/user/card.vue` are fine, and a top-level
`components/card.vue` is not. Give it a real name rather than reaching for a disable
comment.

## Data fetching

Use `useFetch` or `useAsyncData` in setup, and `$fetch` only in event handlers.

```vue
<script setup lang="ts">
const { data, status, error, refresh } = await useFetch('/api/stations')

async function onSubmit() {
  await $fetch('/api/something', { method: 'POST', body: { /* ... */ } })
}
</script>
```

A bare `await $fetch(...)` in setup is the trap: it runs on the server and again on
the client during hydration, so the request happens twice and the payload transfer
does nothing. `useFetch` wraps `useAsyncData` plus `$fetch` and adds the result to
the Nuxt payload, which is what makes one request enough.

The GBFS feed is an external, third-party API. Fetching it through a `server/api/`
route rather than from the browser is the option worth reaching for first: it gives
somewhere to cache, keeps the upstream URL out of the client, and sidesteps CORS.
Note that Nuxt forwards client headers when `useFetch` runs server-side, which is
fine for our own routes and something to be deliberate about for anything upstream.

## Vue

`<script setup lang="ts">`, single-file components, Composition API. No Options API
and no `defineComponent` wrapper; nothing here needs either.

## Tooling notes

`nuxt.config.ts` sets `eslint.config.standalone: false` on purpose, so `@nuxt/eslint`
contributes only the Nuxt-specific rules and the JS, TS and Vue setup comes from the
shared preset. `eslint.config.mjs` then composes them with `prepend`, which is
load-bearing: `append` would put house style last and silently defeat the exemption
layer described above. Neither is a knob to turn while debugging a lint error.

Lint from the repo root (`npm run lint`), not from here. One invocation covers this
package through nested config lookup.
